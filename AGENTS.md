# openIMIS Development Environment — Agent Guide

This repository (`openimis-dev-tools`) is a **local development workspace** that assembles the openIMIS backend and frontend from many independent module repositories. Agents working here should understand which tree is the **assembly** (shell) and which trees are the **packages** (modules).

## Repository layout

```
openimis-dev-tools/
├── backend/              # Django assembly shell (openimis-be_py)
├── backend-packages/     # Cloned backend module repos (one directory per module)
├── frontend/             # React/Vite assembly shell (openimis-fe_js)
├── frontend-packages/    # Cloned frontend module repos (one directory per module)
├── python/               # Setup and release scripts
├── compose.yml           # Docker Compose orchestration
└── .vscode/launch.json   # Dev-tools level debug config (Docker remote attach)
```

## Assembly model

openIMIS is **modular**. The runnable applications live in `backend/` and `frontend/`, but most feature code lives in sibling package directories and is wired in at install time.

### Backend

| Path | Role |
|------|------|
| `backend/` | Django project shell: `openIMIS/`, `openimis.json`, Docker/CI scripts |
| `backend-packages/<module>/` | Individual Python module (e.g. `core/`, `workflow/`, `claim/`) |

- `backend/openimis.json` lists modules and their `pip` sources (git URLs for CI/production).
- `backend/openimis-dev.json` is the **local dev override**: each module points at `backend-packages/` via editable installs (`-e file:…`).
- Generated by `python python/setup-local-dev.py`, which clones or updates repos under `backend-packages/`.

The assembly installs modules with:

```bash
cd backend/script
python modules-requirements.py ../openimis-dev.json > modules-requirements.txt
pip install -r modules-requirements.txt
```

Each package under `backend-packages/` is its own git repository (e.g. `openimis-be-core_py` cloned into `backend-packages/core/`).

### Frontend

| Path | Role |
|------|------|
| `frontend/` | Vite/React shell: `src/modules.jsx`, `openimis.json`, proxy config |
| `frontend-packages/<ModuleName>/` | Individual npm module (e.g. `CoreModule/`, `ClaimModule/`) |

- `frontend/openimis.json` lists modules and their `npm` sources.
- `frontend/openimis-dev.json` is the **local dev override**: each module points at `frontend-packages/` via `file:` paths.
- `node openimis-config-vite.js -c openimis-dev.json` regenerates `package.json` dependencies and `src/modules.jsx`.

Each package under `frontend-packages/` is its own git repository (e.g. `openimis-fe-core_js` cloned into `frontend-packages/CoreModule/`).

## Typical agent workflow

1. **Identify scope** — Is the change in an assembly (`backend/`, `frontend/`) or a module (`backend-packages/*`, `frontend-packages/*`)?
2. **Work in the module repo** — Most feature changes belong in the relevant package directory (separate git repo).
3. **Test through the assembly** — Backend modules are exercised via Django in `backend/openIMIS/`; frontend modules via `frontend/` dev server.
4. **Sync all repos** — `sync.sh` pulls dev-tools, both assemblies, and every package repo.

## Initial setup

```bash
pip install -r requirements.txt
# Configure python/config.py (GitHub token, branches, SSH/HTTPS mode)
python python/setup-local-dev.py
```

## VS Code workspaces

- `backend.code-workspace` — opens `backend/` + `backend-packages/` together (recommended for backend module work).
- Root `.vscode/launch.json` — remote attach to `backend-dev` / `backend-debug` Docker containers with path mappings for both `backend/` and `backend-packages/`.

## Key conventions

- **Do not commit secrets** — `python/config.py`, `.env` files are local only.
- **Branch defaults** — `develop` for modules and assemblies (configurable in `python/config.py`).
- **Module naming** — Backend logical names use underscores (`tasks_management`); frontend module directories use PascalCase + `Module` suffix (`TasksManagementModule`).
- **Changes flow upstream** — Commits and PRs go to each module's own GitHub repo, not to `openimis-dev-tools` (except dev-tools scripts themselves).
